Driver Job Sheet — Phone

390 × 844 · the primary artboard. Route /dashboard/jobs/[id].

This screen is designed phone-first, inverting the hub's usual order. Every other hub screen is desktop-first with a phone pass — lg: appears 67 times across the driver hub and max-*: zero times. A driver reads a job sheet standing at a loading bay, one-handed, in daylight, possibly gloved, so the 390 column is the design and the 720px desktop column is the pass.

Quiet, dense, information-first admin surface: white cards, 1px hairline borders, 14px card radii, mono numerics, colour only for status. Not neobrutalism — zero hard-offset shadows anywhere on this sheet. Light mode only.

How to read the frames Each frame is 390px wide and drawn at its full scroll height so nothing clips. The dashed rule marks where the real 844px viewport ends. The action bar is position: sticky; bottom: 0 — in the product it is pinned to the viewport, not to the end of the scroll.

Two shell facts Below lg the 248px sidebar disappears entirely and the page-title bar stops being sticky — deliberately: pinning a 60px bar, a 44px job strip and a two-line title block on a 390×844 screen would spend a fifth of the viewport on chrome. The top bar drawn in each frame is that shell, for context only.

Money ₾186.40 is driverPayout — the driver's own commissioned share, at 26px / 600 / tracking-[-0.02em] / tabular-nums. The client's price, baseFare, distanceFare, timeFare, helperFee, overtimeFee and serviceLevelAdjustment appear nowhere on this screen — they are excluded at the select level from every driver-facing query, so they never arrive.

Status pill · ACCEPTED reads “Scheduled” toHubJobStatus collapses PENDING, CLAIMED and ACCEPTED into "Scheduled", which hubStatusTone() maps to neutral. The pill is the closed set of six — in transit → info, completed → success, cancelled → danger, scheduled → neutral. No seventh tone. Shape, quoted verbatim: h-auto rounded-full border-transparent px-[9px] py-[3px] text-[11px] font-semibold tracking-[0.02em]. The page itself still needs the raw OrderStatus, because that is what gates the two buttons.

Timeline — three points, and only three Order placed (createdAt), Picked up (inTransitAt), Dropped off (completedAt). Order carries no acceptedAt, claimedAt, dispatchedAt or cancelledAt, so there is no fourth or fifth step to draw. Dots reuse jobs-detail-panel.tsx verbatim: done = filled oklch(59.6% 0.145 163.225), current = hollow accent, pending = hollow border-grey.

Net-new · Navigate There is no navigation handoff anywhere in the repo — zero matches for maps.google, geo:, waze or window.open. This control is new behaviour and needs platform branching: iOS maps://?daddr=… then comgooglemaps://?daddr=…, Android geo:0,0?q=…, web fallback https://www.google.com/maps/dir/?api=1&destination=….

Null lat/lng is the default state, not an edge case scripts/seed-driver-hub-personas.ts never sets coordinates, so every persona order — and this frame — has pickupLat/pickupLng/dropoffLat/dropoffLng all null. Navigate therefore ships as an address-text search, not a coordinate route, and the distance line is an em dash with a sentence saying why. Nothing is disabled: an address search still gets the driver there. If coordinates ever exist, the same button switches to destination=lat,lng and the distance line fills in — no new layout.

Call tel: on a full-width 44px row, with the number also printed as selectable mono text — drivers routinely copy it into WhatsApp rather than dialling. toTelHref already falls back to plain text when a stored number has no digits in it; in that case the row loses its href and keeps the number.

Touch 44px floor on every control (TOUCH_TARGET_CLASSES = "h-11 text-sm font-medium"), 56px on Start delivery and Mark delivered — the only two controls that write. The back chevron is a 44px hit box around an 18px glyph.

Waiting time has no UI precedent anywhere in the product The API returns 400 without it, so it is required, whole minutes, default 0. Drawn as a 44px number input with a min unit affix — a new pattern; nothing in src/components/ui/ composes an input with a suffix today.

receivedBy is not on Order Keeping the field needs a nullable column and an extension to complete, which today accepts only { waitingMinutes }. It wears a SampleNote because it is fed by nothing. Drop the field and the schema gap disappears with it.

Open question 3, answered here: yes, show the effect complete computes overtimeFee = max(0, waitingMinutes − freeLoadingMinutes) × overtimeRatePerMinute and then the driver's commissioned share of it — so the number the driver types changes their own pay. Asking for it without saying so is the one thing this dialog must not do. The line is badged sample because both rule inputs are computed client-side for the preview and the server recomputes on submit; the two must never be allowed to disagree silently. No actions. A driver cannot reopen, amend or cancel a delivered job — no endpoint exists.

The “Delivered” pill is a label, not a status key hubStatusTone("Delivered") is unmapped and would fall through to neutral. The pill must be <HubStatusBadge status="COMPLETED" label="Delivered" /> — completed → success. A real trap: pass the copy string as the status and the pill silently goes grey.

Two payout lines, never six buildFareLines in jobs-detail-panel.tsx yields Payout and, only when the amount is non-zero, Overtime payout · N min loading. A payout is one commissioned lump taken off the whole client-paid total, stored once at booking — there is no carrier-side base/distance/time component to print. The overtime line is conditional on the amount, not on waitingMinutes: a job that waited inside the free allowance earns nothing extra, and a zero line would invite the driver to hunt for money that is not there.

No bottom bar here The persistent bar is the primary-action pattern; a state with no primary action removes the bar rather than showing a disabled one. The sheet ends with a plain sentence saying why.

Three refusals, three sentences — and the pill never moves The status pill above still reads Scheduled, because it reflects the server, not the tap.
· 409 from start → “This job has already moved on. Pull down to refresh.”
· 403 from either → “This delivery isn’t assigned to you any more.”
· 400 from complete → the waiting-time field takes the error inline, beside the control that caused it, and the dialog stays open.
Network failure → the sentence above. In every case the button returns to its idle label and stays tappable.

The error line is role="alert" inside the bar Not a toast — none exists. Placing it in the bottom bar keeps the message and the control that produced it on screen together, above the fold, without moving the 56px button. While a request is in flight the button label becomes Starting… and a role="status" aria-live="polite" line replaces the alert.

Notes carried out of this artboard

Everything drawn here that does not exist yet · The route. /dashboard/jobs/[id] would be the first dynamic segment in the hub.
· The two transition buttons. The endpoints exist; no UI has ever called them.
· Navigate. Nothing in the repo does a map handoff.
· The waiting-time field. No precedent anywhere in the product.
· An input with a unit affix. Not composable from the 15 files in src/components/ui/ today.
· receivedBy. No column.
Nothing else on this sheet is new: contacts, timeline, payout lines, route stops, cargo spec and handling pills are all reused from jobs-detail-panel.tsx, loads-detail-parts.tsx and loads-drawer.tsx.

Both trees mount at once The load board established that the mobile and desktop trees mount simultaneously and CSS picks between them — there is no JS viewport detection anywhere in the feature. Any portalled sheet must therefore carry lg:hidden on both the content and the scrim, and be modal={false} so it does not freeze the desktop tree behind it. The confirmation dialog above is the exception: it is the same dialog on both artboards, so it stays modal and is not duplicated per tree.

Copy that must change when this ships JOB_SHEET_TITLE in loads-detail-parts.tsx — “Job sheet isn't built yet. Client contact details and proof of delivery will live there.” — is deleted, and the three “Open job sheet” buttons lose disabled (loads-drawer.tsx:359, loads-detail-sheet.tsx:386, loads-mobile.tsx:559). ClaimedByYouNote stays — it becomes true. The phrase “proof of delivery” must not survive: v1 captures no photo, no signature, no media of any kind. Delivery is confirmed by a state transition, not by evidence.

Open question 5 — future-dated jobs Not resolved here. scheduledAt can be days out, and start refuses nothing on date grounds — it only checks status — so today a driver could legally start a job scheduled for Friday. This artboard draws the same screen with the same live button; if that is wrong, the fix is a server-side window, not a disabled button, because a disabled button with no server rule behind it is a suggestion.
