Driver Job Sheet — Desktop

Single column, max-width: 720px. The desktop pass, not the design: this screen is drawn phone-first at 390 × 844 and the 720 column is what that layout becomes when the viewport allows it.

Why 720, not 1180 Every other hub screen spreads to the 1180px content column because it is a dashboard — a table with a detail panel beside it. This is a task list a driver reads top to bottom, and the only thing a wider column buys is longer line lengths on addresses. Above lg the 248px sidebar returns and the page-title bar becomes sticky again; below it both disappear.

What changes between the two artboards, and what does not Changed: the persistent bottom bar becomes an inline action in the job header (a bar pinned to a 1440px viewport under a 720px column is a phone pattern wearing a desktop coat); controls drop from the 44/56px touch floor to h-10 text-sm font-medium, the hub's desktop action; the page title goes 17px → 20px; the two stops share one Route card instead of two. Unchanged: every token, every pill, the card geometry, the copy, the three timeline points, the money rule, and the dialog — which is the same component at both widths, at its real 440px here.

Waiting time — required, and it changes the driver's own pay POST /api/orders/[id]/complete returns 400 without it. Whole minutes, default 0. overtimeFee = max(0, waitingMinutes − freeLoadingMinutes) × overtimeRatePerMinute, and the driver receives their commissioned share of it — so the preview line answers open question 3 in the affirmative: showing the effect is the only honest way to ask for the number. It is badged sample because the preview is computed client-side and the server recomputes on submit. Open question 1 remains open: this is the field, not a timer; a timer would be more accurate but needs arrival timestamps, and none exist. receivedBy needs a nullable column and an extension to an endpoint that today accepts only { waitingMinutes }.

An input with a unit affix is new component work src/components/ui/ has 15 files — badge, button, calendar, card, checkbox, dialog, dropdown-menu, input, label, popover, select, sheet, table, tabs, textarea. There is no tooltip, toast, progress bar, separator, avatar, skeleton or accordion, and no input group. The min affix drawn above is a new composition, flagged rather than assumed.

No actions. A driver cannot reopen, amend or cancel a delivered job — no endpoint exists.

“Delivered” is a label, not a status key hubStatusTone("Delivered") is unmapped and falls through to neutral. The pill must be <HubStatusBadge status="COMPLETED" label="Delivered" /> so completed → success resolves. Pass the copy string as the status and the pill silently goes grey.

Two payout lines, never six buildFareLines yields Payout and, only when the amount is non-zero, Overtime payout · N min loading. A payout is one commissioned lump taken off the whole client-paid total and stored once at booking; there is no carrier-side base, distance or time component to print. The overtime line is conditional on the amount, not on waitingMinutes — a job that waited inside the free allowance earns nothing extra, and a zero line would send the driver hunting for money that is not there.

Departure from the copy table — deliberate The copy table gives This delivery isn't assigned to you. for “Not yours”, but the same brief requires a not-found indistinguishable from a missing id. The two contradict: naming assignment confirms the order exists and belongs to someone else, which is exactly the id-probing the orders/[id]/track pattern blocks — “Someone else's order is reported exactly like a missing one, so this page can't be used to probe which order ids exist.” This screen therefore reuses that page's own wording, “Order not found.”, and the assignment string moves to the load board's “you no longer hold this load” path, where the reader is already known to have held it.

Three refusals, three sentences — and the pill never moves The pill still reads Scheduled, because it reflects the server, not the tap.
· 409 from start → “This job has already moved on. Refresh to see where it is.”
· 403 from either → “This delivery isn’t assigned to you any more.”
· 400 from complete → the waiting-time field takes the error inline and the dialog stays open.
Network failure → the sentence drawn above. In every case the button returns to its idle label and stays clickable. The message is a role="alert" line beside the control that produced it, and the in-flight state is role="status" aria-live="polite" — not a toast, because there is no toast in this codebase.

Notes carried out of this artboard

Everything drawn here that does not exist yet · The route. /dashboard/jobs/[id] would be the first dynamic segment in the hub; hubNavItemForPath prefix-matches it to “My orders” with no change.
· The two transition buttons. Endpoints exist; no UI has ever called them.
· Navigate. Zero matches for maps.google, geo:, waze or window.open in the repo. Needs platform branching: maps://?daddr=… · comgooglemaps://?daddr=… · geo:0,0?q=… · https://www.google.com/maps/dir/?api=1&destination=….
· The waiting-time field and the unit-affixed input. No precedent anywhere.
· receivedBy. No column.
· A third view model. HubJob has contacts, timeline and money but no cargo; HubLoad has cargo and windows but no timeline or raw status. The job sheet unions them.
Everything else is reuse: contacts, timeline, payout lines, route stops, cargo spec and handling pills already ship at production quality in jobs-detail-panel.tsx, loads-detail-parts.tsx and loads-drawer.tsx. Extract the shared parts — do not copy them a third time.

Where the data comes from Not GET /api/loads — it serialises status as only "available" | "claimed" | "mine", and telling ACCEPTED from IN_TRANSIT is exactly what gates the two buttons. There is no GET /api/orders/[id] either. The page reads Prisma server-side following orders/[id]/track/page.tsx: server component, dynamic = "force-dynamic", auth.api.getSession, ownership check, generic not-found. Contacts are redacted by nulling the six keys rather than omitting them, so every row keeps one shape; the sheet is only reachable by the assigned driver, so they are always present here. Use CARRIER_ORDER_PARTY_SELECT — ORDER_PARTY_SELECT, which specs/driver-load-board/action-required.md names, is dead code.

Out of scope for v1, and it must stay out of the copy No map embed, no delivery photos, no signature, no captured media of any kind. Delivery is confirmed by a state transition, not by evidence. JOB_SHEET_TITLE in loads-detail-parts.tsx currently promises “proof of delivery” — that string is deleted when this ships, along with disabled on the three “Open job sheet” buttons (loads-drawer.tsx:359, loads-detail-sheet.tsx:386, loads-mobile.tsx:559). ClaimedByYouNote stays: it becomes true.

Two stops, and the layout could extend The schema supports exactly one pickup and one dropoff — six columns rather than a Stop relation, documented as reversible. The Route card is a vertical list of marker + block, so a third stop is a third list item, not a redesign. “2 stops” is a constant, not a field.
